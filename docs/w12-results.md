# W12 每日结果、积分迁移与历史重算实现说明

> 前置：W00、W01、W10、W11  
> 协议：保持 `DST1` / `v=1`  
> 数据库：保持 Room v3

## 已实现

- 使用纯领域计算器统一计算分组和全局每日结果；
- 支持 `COMPLETED`、`INCOMPLETE`、`IN_PROGRESS`、`OPTIONAL_ONLY`，无有效任务使用空结果表示；
- 取消和未开始实例不进入当前结果；
- 实际积分始终来自 `points_ledger.delta` 净和，修改任务当前分值不会追溯改分；
- 结果任务的分组和必做属性采用当前任务定义，实例继续保留生成时快照；
- 单日结果使用一条聚合查询读取，日期范围摘要使用一条范围聚合查询，不逐实例查询积分；
- 完成、撤销、导入、取消、恢复、分组移动、重复实例生成和截止状态校准均触发结果重算；
- 变化前快照、业务写入、积分迁移和 `result_revision` 在同一个 Room 事务中提交；
- 修订记录保存新旧状态、新旧积分、原因、批次和规范化相关任务 ID；
- 当前结果不另建缓存表，`result_revision` 仅作为审计时间线；
- `DstApplication` 对后续 UI 暴露只读 `ResultRepository`。

## 结果规则

对非取消、已开始的有效任务按以下优先级计算：

1. 任一必做任务为 `MISSED`：`INCOMPLETE`；
2. 没有错过但存在必做 `PENDING`：`IN_PROGRESS`；
3. 存在必做且全部完成：`COMPLETED`；
4. 没有必做但存在选做：`OPTIONAL_ONLY`；
5. 没有有效任务：不生成结果。

组选做任务不会降低必做任务结果。组完成和未完成状态分别读取组的 `completeMessage` 和 `incompleteMessage`。

## 历史积分迁移

任务移动分组时不改写原流水，而是按 `(taskId, occurrenceKey, groupId)` 的净余额写入补偿流水：

```text
旧组  GROUP_TRANSFER_OUT  -balance
新组  GROUP_TRANSFER_IN   +balance
```

因此：

- 每个重复实例的历史积分独立迁移；
- 全局净积分不变；
- 原完成和撤销流水保持可审计；
- 再次执行时旧组余额为零，不会重复迁移；
- 移动后的完成和撤销均使用任务当前分组记账。

## 事务与幂等

结果敏感写入遵循固定顺序：

```text
捕获旧结果 → 执行业务变化 → 捕获新结果 → 比较作用域 → 写修订 → 提交
```

同一批次由 `batchId` 拦截；完成和撤销由实例状态拦截；实例生成使用联合主键和 `INSERT IGNORE`；积分迁移使用净余额归零；没有状态、积分或结果成员变化时不写修订。事务失败时业务数据、流水和修订一起回滚。

## 对外读取接口

`ResultRepository` 提供：

- `getDailyResult(taskDate)`：组和全局单日结果；
- `getGroupResult(taskDate, groupId)`：单组结果；
- `getRevisionTimeline(taskDate)`：结果修订时间线；
- `getDailySummaries(fromDate, throughDate)`：日期范围摘要。

这些接口供 W23 历史页、W24 结果页和 W30 统计页复用。
