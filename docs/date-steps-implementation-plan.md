# 日期默认值与分步骤执行实施约定

本文件记录本次用户批准的实现与验收范围。由 Luna 实现，主代理审查；不包含 Git 推送、GitHub Releases 或云端部署。

## 日期与快照

- 新布置临时任务的归属日期、重复任务开始日期留空时，采用布置时的自然日。联网使用空间时区，离线使用网页任务时区设置（默认浏览器时区）。
- 编辑已有任务保留原日期；主动清空表示当天。旧记录本来没有日期且未触碰字段时保持原语义。明确日期不覆盖。草稿和模板不提前固定日期。
- UI 显示“留空默认今天”及具体日期。未知空间时区应提示刷新，不使用 UTC 猜测。
- 离线预览生成一次不可变的规范化快照，包括日期、步骤 ID、batchId、任务/例外载荷；任务码、批次历史、任务库和修订记录均取这份快照。编辑草稿使旧预览失效。跨午夜确认不得重新计算。
- 联网保存时固定载荷，排队、重试、延迟接收不重算日期。
- Android TaskDay 保持 04:00 换日，默认截止保持任务日次日 04:00；精确截止留空仍报错，永不截止不变。

## 步骤交互与状态

- 每步有名称、必需/选做和直接完成、计数、计时、填写信息、心情记录五种完成方式。限制沿用已有类型；文字上限 2000 Unicode code points。
- 有步骤的新模式隐藏任务级执行选择；删掉所有步骤恢复直接完成。只在最后主动完成整个任务时结算一次积分。
- 按顺序开放步骤，后续锁定；选做可以明确跳过。达标后手动确认此步骤，不自动确认。已确认步骤只读摘要，可撤销。
- 必需步骤全部确认即可完成整项；尚未确认的选做项最终记为跳过，事先提示，其草稿不提交。
- 撤销步骤：从该步骤起清空确认/跳过标记，保留输入和进度，重新顺序确认。整项完成锁定；整项撤销保留答案和步骤确认状态，编辑权限遵循现有状态/截止规则。
- 一次只运行一个计时器，暂停、页面离开、失去前台时保存并暂停。失败保留待保存进度；重试不能重复累计。
- 文字编辑停止 500ms 自动保存，返回/切换/确认/完成前及时保存。同实例写入串行并校验编辑版本，旧异步写不可覆盖新值。失败不能确认或完成。

## 跨端接口（共同约定）

- 任务 `u:{k:5}` 为 `STEPS`；旧 `u` 省略或 k1..4 携带旧 `s` 时保持旧执行语义。
- 新步骤 `{i,n,r,u?}`：i 为 16 字符协议 ID，n/r 沿用既有定义；u 只能是叶子类型 k1..4，省略是直接完成。禁止嵌套 k5。STEPS 要求 1..50 步及唯一 i。
- 新增步骤使用既有随机协议 ID。转换旧步骤时使用确定性规则：`s` + taskId 前 12 字符 + 原始零基位置的三位小写 base36；原任务级执行转换的附加步骤 ID 为 `r` + taskId 前 12 字符 + `000`。生成一次后写入定义，后续排序/改名沿用已有 i，绝不能按新位置重新生成。不同任务的 ID 由 taskId 命名空间隔离。
- 本机状态为 PENDING/CONFIRMED/SKIPPED，锁定状态根据顺序计算。事件使用原 EXECUTION_EVENT；仅整项完成发送 `data.executionKind = "STEPS"` 和 `data.stepResults`。
- stepResults 按实例快照顺序列出每步：`{stepId,status,...answer}`，status 为 CONFIRMED 或 SKIPPED。直接完成无 answer；计数为 counterValue；计时为 elapsedMillis；信息为 informationContent；心情为 moodRating 和 moodText。SKIPPED 仅允许选做，不能有答案字段。不提交 PENDING 或草稿。
- 结果中的任务修订、实例、日期例外使用现有事件外层关联。服务端按有效定义校验步骤集合、顺序、类型、状态和答案范围；不新增逐步云事件。撤销事件无 stepResults/答案。沿用权限、幂等、旧修订审查和结果选择，旧完成不能覆盖较新撤销。
- 服务端校验后按对应修订和例外给每个 stepResults 补充只读 `name:string`、`required:boolean`、`execution:叶子u或null` 元数据快照。客户端上行不必提供这些字段；服务端不得信任自报标签。Web 使用事件快照展示，不能拿最新 task 定义为历史结果补标签；STEPS 结果不回退到旧任务级 information_submission。
- Android 历史和 Web 管理员结果以提交快照展示，名称与类型解析对应修订及日期例外；通用分享图不加正文。

## 更新、迁移与备份

- Room 8：按任务/实例/稳定 stepId 保存定义快照、顺序、状态、进度、草稿及提交答案；每天实例独立。数据库升级不自动转换旧执行模式。
- 明确编辑旧任务时转换为 STEPS，原任务级特殊执行追加为必需步骤；超过 50 步提示调整，不丢要求。现有规则允许修改的未完成实例同时转换，保留可对应进度/答案，重新顺序确认。已完成历史不变，未来实例使用新定义。
- 改名保留数据；重排保持步骤归属，但从首个受影响顺序处重新确认；新增初始未完成；删除清掉不适用数据；类型/参数改变清掉不兼容进度并重新确认后续步骤。
- 例外按基础+例外求有效定义。切入 STEPS 必须得到完整有效步骤集；切出必须明确清空步骤。Web/Cloud/Android 校验一致；旧客户端拒绝新类型整个批次，编辑端提示升级。
- DSTB1 payload 4，读取旧版本；保存步骤身份、定义/例外配置、每实例状态/草稿/提交快照。合并先按现有规则选择实例，再恢复同源完整步骤集，不能把不同版本逐条拼接；新撤销不被旧完成覆盖。
- Web 备份支持新配置，更新产品/协议/备份和迁移文档。
