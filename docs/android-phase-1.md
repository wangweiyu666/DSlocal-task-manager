# Android 第一阶段实现边界

本阶段用于建立可复用的协议、领域和数据库测试基础，应用版本仍为 `0.1.0-alpha`，协议保持 `DST1` / `v=1`。

## 已实现范围

- DST1 外层 Base64URL、CRC32、zlib、严格 UTF-8 与大小限制；
- 严格 JSON 字段、类型、ID、日期、文本和集合验证；
- 普通任务与步骤任务；
- 独立协议测试向量；
- 导入预览、批次去重与 Room 单事务写入；
- Dom 名称、批次、积分组、任务定义、实例和步骤持久化；
- 未开始、待完成、已完成、未完成、已撤销状态基础；
- 步骤完成门槛、任务完成、撤销完成；
- 不可变操作日志和积分冲正流水；
- 按任务日、积分组和状态查询历史数据；
- 最小 Compose 粘贴、预览、确认导入流程。

## 暂不支持

测试版本识别但整批拒绝以下 DST1 v1 能力：

- `x`：重复规则；
- `h`：提醒；
- `u`：计数、计时和信息告知执行方式。

延期、重复实例生成、历史结果重算、完整历史 UI、结果图片和备份恢复后置。能力从“不支持”变为“支持”不需要升级 DST1；只有业务语义发生不兼容变化才升级协议主版本。

## 测试阶段临时积分规则

任务移动积分组时，既有 `points_ledger` 条目保留完成当时的 `groupId`，移动后的新完成记录计入新积分组。这与需求稿中“历史积分随任务移动并重算结果”的正式语义不同。

正式实现历史结果重算时，必须移除此临时规则，迁移受影响的积分流水，并生成结果修订记录。

## 数据库兼容策略

W01 已将 Room 基础模型冻结为版本 3，移除破坏性重建，并提供 `1→2→3` 显式迁移。后续版本必须提交连续 migration、对应 Schema JSON 和数据保留测试。

正式结构、外键策略和模块边界见 `docs/android-database-v3.md`。
