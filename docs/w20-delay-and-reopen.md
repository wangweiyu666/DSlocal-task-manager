# W20 延期、重新开启与显式日期迁移实现说明

> 前置：W11、W12  
> 协议：保持 `DST1` / `v=1`  
> 数据库：保持 Room v3

## 已实现

- DST1 解析模型保留 `y`和 `l`是否显式出现；
- 新任务缺少 `y`时仍按截止或当前任务日推导日期；
- 已有任务缺少 `y`时保留原日期，解析得到的推导日期不会触发迁移；
- 只有显式且不同的 `y`才产生日期迁移；
- 使用纯 `InstanceUpdatePlanner`统一预览和正式导入的日期、截止与状态判定；
- `MISSED`任务延长到未来截止后恢复为 `PENDING`；
- 延长后的截止仍在过去时继续保持 `MISSED`；
- 已完成任务不会因延期重新开启；
- 已完成任务显式移动日期时保持完成状态和原积分流水；
- 延期和重新开启保留实例步骤、执行进度、正文与备注；
- 日期迁移通过实例日期关联移动历史积分，不改写或复制原积分流水；
- 导入预览显示旧/新日期、截止、状态、迁移净积分和历史影响；
- 操作日志区分 `DEADLINE_EXTENDED`、`TASK_REOPENED`和 `TASK_DATE_MOVED`；
- W12 结果修订增加延期、重开、日期迁移和混合批次原因；
- 重复任务某次延期继续使用新 taskId 的独立 `TEMPORARY`任务，不增加来源关联字段。

## 日期解析规则

日期处理顺序固定为：

```text
解析显式指令 → 解析更新上下文中的最终 taskDate → 计算 deadline → 规划状态变化
```

对于已有任务：

```text
y 缺失       → 保留旧 taskDate
y 显式且相同 → 日期不变
y 显式且不同 → 日期迁移
```

`l`缺失仍恢复为最终归属日期次日 04:00；`l:null`表示永不截止。

## 状态恢复规则

`MISSED`只允许通过 Dom 完整新版产生的合法延期或显式日期移动恢复。系统时间回拨和普通前台校准不会恢复状态。

```text
MISSED + 更晚未来截止 → PENDING
MISSED + 更晚过去截止 → MISSED
MISSED + 永不截止     → PENDING
COMPLETED + 任意延期  → COMPLETED
```

显式日期移动后的非完成实例按新日期和截止时间重新计算为 `NOT_STARTED`、`PENDING`或 `MISSED`。

## 日期积分迁移

积分流水没有冗余任务日期，日期归属通过 `(taskId, occurrenceKey)`关联实例。因此日期移动只受控更新单次实例的 `taskDate`：

```text
旧日期结果移除实例积分
新日期结果加入同一实例净积分
全局累计积分不变
原 points_ledger 不变
```

如果同时移动积分组，继续使用 W12 的成对组补偿流水。

## 幂等与事务

导入确认后在一个 Room 事务中重新生成更新计划、捕获旧结果、更新定义和实例、迁移组积分、写操作日志并写结果修订。`batchId`阻止同一事件重放；不同批次的相同最终内容不会再次重开、迁移积分或产生结果修订。

## 测试覆盖

- 缺少 `y`保留旧日期；
- 显式不同 `y`才迁移；
- 延期到未来后重新开启；
- 延期仍在过去时不重新开启；
- 永不截止和默认截止；
- 已完成任务不重新开启；
- 延期保留步骤进度；
- 已完成积分随日期归属移动但流水不变；
- 同内容不同批次不重复重开或写结果修订；
- 重复 occurrence 与新临时任务保持独立；
- W00～W12 全量回归和调试 APK 构建。

## 后续边界

- W21 根据 W20 暴露的实例日期和截止变化重新安排本地提醒；
- W22/W23 只消费预览与历史数据，不重新实现延期判定；
- Dom 正式任务库负责生成重复任务某次延期所需的新 taskId 临时任务；
- 不增加重复来源字段，不修改既有 occurrence key。
