# W10 计数、计时和信息告知实现说明

> 前置：W00、W01  
> 协议：保持 `DST1` / `v=1`  
> 数据库：保持 Room v1.3

## 已实现

- 将 `u.k=1/2/3` 解析为强类型 `ExecutionSpec`，合法向量不再返回 `CAPABILITY_NOT_IMPLEMENTED`；
- 将执行方式、交互方式和目标写入任务定义及实例快照；
- 使用 `(taskId, occurrenceKey)` 作为所有执行服务入口；
- 计数值限制、计时累计与目标截断、告知正文校验和草稿保存；
- 必需步骤与执行目标共同限制显式完成操作；
- 完成时锁定执行数据，撤销完成后保留步骤、计数、计时和告知正文；
- 执行配置更新时重置未结束实例进度，并在 `action_log` 保存旧进度摘要；
- 信息告知要求更新时保留草稿并在导入预览中提示复核；
- 前台计时使用可注入单调时钟，离页或进入后台时暂停并结算；
- 提供 `ExecutionViewModel`、`ExecutionUiState` 和 `TimerSessionController` 作为 W22 接口基础。

## 完成门槛

任务必须处于 `PENDING`，必需步骤全部完成，并满足对应执行目标：

| 类型 | 执行目标 |
|---|---|
| `NORMAL` | 无额外目标 |
| `COUNTER` | 当前值达到导入目标 |
| `TIMER` | 累计毫秒达到目标秒数 |
| `INFORMATION` | 正文去空白后非空且不超过 2000 个 Unicode 码点 |

达标不会自动完成；只有显式完成操作会更新实例、设置告知提交时间、发放积分并写入日志。

## 更新规则

- 计数交互方式或目标变化：未开始/待完成实例进度归零；
- 计时目标变化：未开始/待完成实例累计时间归零；
- 执行类型切换：归档旧类型和数值摘要，删除当前活动进度；
- 信息要求变化：保留草稿，预览标记 `INFORMATION_REVIEW_REQUIRED`；
- 已完成、未完成和已撤销实例保持历史快照和执行数据。
