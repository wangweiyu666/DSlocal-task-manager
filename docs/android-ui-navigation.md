# Android UI 与返回导航

本文汇总 W22～W31 已形成的 Android UI 层级、返回职责和动效边界，避免各窗口重复定义导航行为。

## 页面层级

| 层级 | 页面 | 返回行为 |
|---|---|---|
| 一级 | 历史、今日、我的 | 底部导航切换；根页面系统返回交给 Activity 和系统处理 |
| 二级路由 | 当日历史、积分流水、已归档积分组、设置、备份与恢复 | Navigation Compose 管理返回栈和预测式返回 |
| 恢复流程 | 备份预览、冲突处理、进度与结果 | 写入前返回直接放弃；执行中返回不取消后台任务；结果完成后回到今日 |
| 详情路由 | 今日任务详情、历史只读详情 | 返回前保存备注，再弹出路由；手势进度由统一预测返回组件驱动 |
| 页内结果 | 今日结果 | 返回今日页；保留下拉进入和末尾上滑关闭交互 |
| 全屏覆盖层 | 分享图片预览 | 返回原结果页或详情页；隐私确认对话框显示时优先关闭对话框 |

所有可见返回入口统一使用 `BackNavigationIcon`，图标、点击区域和“返回”语义保持一致。页面不再各自绘制“返回”文字按钮。

## 预测式返回

- Manifest 显式启用 `android:enableOnBackInvokedCallback="true"`；
- AndroidX Activity Compose 1.10.0 与 Navigation Compose 2.8.5 满足预测式返回要求；
- 普通 Navigation Compose 路由不额外拦截返回，由 `NavHost` 提供手势预览和 pop 动画；
- 根 Activity 不注册返回拦截器，保留 Android 15 及以上的返回桌面系统动画；
- 任务详情、历史详情、今日结果和分享预览因保存或关闭语义需要拦截返回，统一使用 `PredictiveBackHandler`；
- 自定义页面根据手势方向和进度轻微横移、缩放和淡出，取消手势时恢复原状，完成手势后执行原有保存或关闭操作；
- 分享预览中的隐私确认对话框显示时，覆盖层预测返回暂停，由对话框优先消费返回；
- 开启“减少动效”时不绘制预测进度变换，但返回栈和保存语义保持不变。

Android 12 及以下继续通过 AndroidX 返回分发器执行相同完成行为，不需要平台版本分支。

## UI 状态保留

- 底部导航使用 `saveState` / `restoreState`；
- 设置返回“我的”后保留统计周期和列表状态；
- 详情返回前提交当前备注草稿；
- 分享预览返回后保留原结果页或详情页；
- 今日结果返回继续显示今日任务列表，不清空已加载数据。
- 备份预览和冲突选择尚未写库，返回时直接清理临时选择文件；恢复执行中其他业务页面显示只读遮罩；
- 恢复结果保留到用户主动完成，成功后清理旧页面栈并回到“今日”。

## 测试边界

- Compose 仪器测试覆盖设置入口、系统返回和原页面恢复；
- API 35 真机或模拟器负责验证预测式手势的视觉进度与取消恢复；
- API 26 验证旧系统返回兼容；
- Preview 截图覆盖统一返回图标，不模拟系统手势进度；
- Android 13、14 测试预测式返回时需在开发者选项启用相关动画；Android 15 及以上默认启用。

W31 验收结果：JVM 97/97、Preview 截图 18/18、API 35 全量仪器测试 23/23、API 26 W31 关键仪器测试 3/3 通过。自动化覆盖返回完成行为；预测手势的实时进度和取消恢复已在 API 35 手动验证。
