## 1. 项目定位

项目由两个配套产品组成：Dom 端任务生成网页和 Sub 端 Android 本地任务管理应用。双方不建立账号体系，不使用服务器同步任务状态，通过社交软件手动传递任务字符串和结果图片或文本。

### 1.1 Sub 端 Android 应用

主要用途：

- 导入 Dom 生成的任务字符串；
- 在本地查看、执行和记录任务；
- 保存步骤、计数、计时、信息告知、备注和完成历史；
- 计算积分及每日结果；
- 生成当前任务日的结果页面和分享图片；
- 提供本地备份与恢复。

技术要求：

- Kotlin；
- Jetpack Compose；
- Material Design 3；
- Room；
- ViewModel；
- StateFlow；
- Navigation Compose；
- 完全本地运行；
- 不需要账号或服务器；
- 不申请网络权限；
- 不主动联网。

### 1.2 Dom 端任务生成网页

主要用途：

- 新建、更新、撤销和延期任务；
- 管理积分组与任务模板；
- 在一个字符串中生成多个积分组及其任务；
- 生成 DST1 任务字符串并复制发送给 Sub。

技术与数据要求：

- TypeScript 网页；
- 支持手机和桌面浏览器；
- 不需要登录；
- 不保存 Sub 的完成状态、备注、积分和历史；
- 使用 IndexedDB 保存 Dom 创建的积分组、任务定义、重复模板和草稿；
- 支持配置文件导出、导入；
- 支持粘贴旧任务字符串恢复任务定义。

## 2. 总体业务边界

系统不提供：

- 双方账号；
- 在线同步；
- 远程控制；
- 云端任务状态；
- Dom 自动读取 Sub 完成情况；
- Sub 修改 Dom 下发的任务定义；
- 任务内容的加密或数字签名。

任务流程：

```text
Dom 创建任务
→ 生成任务字符串
→ 通过社交软件发送
→ Sub 在 Android 今日页导入
→ Android 校验、预览并确认
→ 本地执行和记录
→ Sub 生成结果图片或信息告知内容
→ 手动发送给 Dom
```

## 3. DST1 传输协议

### 3.1 字符串格式

```text
DST1.<payload>.<checksum>
```

示例：

```text
DST1.xxxxxxxxxxxxxxxxxxxxxxxx.83FA29BC
```

组成：

- `DST1`：协议主版本；
- `payload`：压缩后任务 JSON 的 Base64URL；
- `checksum`：压缩字节的 CRC32。

CRC32 仅用于发现复制、粘贴或传输损坏，不承担防篡改功能。

### 3.2 编码流程

```text
短字段 JSON
→ Unicode NFC
→ UTF-8（无 BOM）
→ zlib 封装 DEFLATE
→ CRC32(compressedBytes)
→ Base64URL(compressedBytes)
→ 去除 = 填充
→ 拼接 DST1.payload.checksum
```

具体要求：

- JSON 不缩进，不添加无意义空格；
- Dom 按固定字段顺序输出，以提高压缩率；
- 解码端不得依赖字段顺序；
- 压缩等级建议为 6；
- 使用 zlib 封装，不使用 raw DEFLATE 或 gzip；
- 不使用预设压缩字典；
- CRC32 输出 8 位大写十六进制；
- JSON 数字均为整数，不使用科学计数法；
- 网页端使用打包进网页的 zlib 兼容实现；
- Android 使用 `java.util.zip.Deflater/Inflater`，`nowrap=false`。

不同平台压缩结果可以不同，只要可以互相解压；CRC32 始终针对实际传输的压缩字节计算。

### 3.3 解码流程

```text
检查 DST1
→ Base64URL 解码
→ CRC32 校验
→ zlib 解压
→ JSON 解析
→ 字段与业务规则验证
→ 导入预览
→ 用户确认
→ Room 单事务写入
```

### 3.4 协议版本

- `DST1`必须与 JSON 中的`"v":1`一致；
- Android 不尝试解析高于自身支持范围的主版本；
- 未知主版本提示“该任务字符串需要更新版本的应用”；
- 改变完成条件、状态、积分或日期语义时必须升级主版本；
- 未知执行类型、任务类型、重复类型和状态枚举必须拒绝；
- DST1 v1 当前没有可忽略字段白名单；任何对象中的未知字段均整批拒绝；
- 普通、计数、计时、信息告知、重复和提醒均属于 DST1 v1。

## 4. 顶层 JSON 结构

```json
{
  "v": 1,
  "b": "batchId",
  "d": "Dom名称",
  "m": "本次导入说明",
  "g": [
    {
      "i": "groupId",
      "n": "积分组名称",
      "cm": "完成文案",
      "im": "未完成文案",
      "t": []
    }
  ],
  "t": [],
  "z": []
}
```

### 4.1 顶层字段

| 字段 | 必需 | 含义 |
|---|---:|---|
| `v` | 是 | JSON 协议版本 |
| `b` | 是 | 本批次 ID |
| `d` | 否 | 全局 Dom 显示名称更新 |
| `m` | 否 | 本批次导入说明 |
| `g` | 否 | 积分组及其任务列表 |
| `t` | 否 | 未分组任务列表 |
| `z` | 否 | 全局撤销任务 ID 列表 |

除 `v`、`b`外，必须至少包含一种实际操作：`d`、`g`、`t`或`z`。仅有批次说明 `m`不构成有效操作。

空的 `g`、`t`、`z`、`s`、`h`直接省略。

### 4.2 Dom 名称

- `d`存在：更新 Android 中的 Dom 名称；
- `d`缺失：保留现有名称；
- `d=""`：清除名称；
- 结果页存在名称时显示，不存在时不留空位。

### 4.3 批次说明

- `m`只属于本批次；
- 显示在导入预览和导入记录中；
- 不影响任务、结果和积分。

## 5. ID 规则

### 5.1 传输 ID

`batchId`、`taskId`、`groupId`均由 Dom 网页生成：

```text
12 字节安全随机数
→ Base64URL 无填充
→ 16 字符 ID
```

- 使用 `crypto.getRandomValues()`；
- 不添加 `b_`、`t_`、`g_`前缀；
- ID 区分大小写；
- ID 必须恰好为 16 个 Base64URL 字符。

| ID | 生成时机 | 语义 |
|---|---|---|
| `batchId` | 每次正式生成字符串 | 一次导入操作 |
| `taskId` | 新建任务 | 同一任务定义或重复模板 |
| `groupId` | 新建积分组 | 跨批次长期积分组 |

相同 `batchId`重复导入时，Android 阻止重复操作。

### 5.2 Android 实例键

单次任务：

```text
taskId + ":once"
```

重复任务：

```text
taskId + ":" + 计划执行日期
```

Room 使用 `(taskId, occurrenceKey)`联合唯一约束：

- 单次任务 `occurrenceKey="once"`；
- 重复任务使用 ISO 日期；
- 防止补建、重复启动或备份合并产生重复实例；
- 实例键不进入 DST1。

积分流水、操作日志和结果版本使用 Android 本地生成的 16 字符随机记录 ID。

## 6. 多积分组结构

一个字符串可以包含多个积分组：

```text
一个批次
├─ 积分组 A
│  ├─ 任务 1
│  └─ 任务 2
├─ 积分组 B
│  └─ 任务 3
├─ 顶层未分组任务
└─ 全局撤销任务
```

### 6.1 积分组结构

```json
{
  "i": "groupId",
  "n": "积分组名称",
  "cm": "全部完成文案",
  "im": "未完成文案",
  "t": []
}
```

积分组不是独立的“任务包”页面，仅用于：

- 任务归类；
- 每日结果计算；
- 积分统计；
- 今日页和结果页的小标题。

同一个 `groupId`可以跨多个批次不断加入临时任务或更新原任务。

### 6.2 积分组采用局部更新

`i`必需，其他字段缺失表示保留原值：

| 字段 | 缺失 | 空字符串 |
|---|---|---|
| `n` | 保留原名称 | 不允许 |
| `cm` | 保留原内容 | 恢复默认完成文案 |
| `im` | 保留原内容 | 恢复默认未完成文案 |

首次遇到未知 `groupId`且缺少名称时，Android 使用“未命名积分组”。

积分组对象至少包含 `i`，并具有 `n`、`cm`、`im`或非空 `t`中的一项实际更新内容。

### 6.3 未分组任务

顶层 `t`表示未分组任务。现有任务出现在顶层 `t`时，移动到“未分组”。“未分组”是系统分组，不能删除或归档。

### 6.4 任务移动

任务出现在哪一层，就归入哪一层：

- 出现在 `g[].t`：归入该积分组；
- 出现在顶层 `t`：归入未分组；
- 移动时全部历史积分一并转移；
- 实际已获得积分数不重新计算；
- 原积分组和新积分组的历史结果重新计算并记录变更。

### 6.5 积分组归档

- 无待完成任务且不再生成重复实例时可以归档；
- 归档后不显示在今日首页；
- 历史、积分和结果记录保留；
- 导入相同 `groupId`的新任务时自动解除归档；
- Sub 可以本地归档或取消归档，但不能修改积分组内容；
- Dom 浏览器删除积分组只删除网页本地配置，不影响 Android。

## 7. 任务数据结构

### 7.1 最小任务

```json
{
  "i": "taskId",
  "n": "任务名称",
  "r": 1
}
```

### 7.2 完整可选结构

```json
{
  "i": "taskId",
  "n": "任务名称",
  "r": 1,
  "d": "任务描述",
  "y": "2026-07-20",
  "l": "2026-07-20T22:00",
  "p": 10,
  "o": 20,
  "s": [],
  "x": {},
  "m": "单任务完成提示",
  "h": [60, 10],
  "u": {}
}
```

| 字段 | 含义 |
|---|---|
| `i` | 任务 ID |
| `n` | 任务名称 |
| `r` | 必做或选做 |
| `d` | 描述或信息告知要求 |
| `y` | 任务归属日期 |
| `l` | 截止时间 |
| `p` | 积分 |
| `o` | 少量情况下使用的人工排序 |
| `s` | 步骤 |
| `x` | 重复规则 |
| `m` | 单任务完成提示 |
| `h` | 截止前提醒分钟数 |
| `u` | 软件内执行方式 |

任务不包含备注权限字段。所有任务始终允许 Sub 添加普通备注。

### 7.3 必做与选做

```text
r=1：必做任务
r=0：选做任务
```

- 必做任务影响当日完成结果和必做完成率；
- 选做任务不影响整体完成与否；
- 必做和选做均可获得积分。

## 8. 任务更新语义

相同 `taskId`表示更新原任务，而不是创建副本。

任务采用完整替换语义：

- 新字符串中存在的字段使用新值；
- 缺失的可选字段恢复默认；
- 不保留旧任务定义中已经缺失的字段。

`y`是上述规则的唯一日期归属例外：新任务缺少 `y`时按日期规则推导；已有同 `taskId`任务更新时缺少 `y`表示保留原归属日期。只有显式提供且不同的 `y`才构成日期迁移。

| 缺失字段 | 默认行为 |
|---|---|
| `d` | 空描述 |
| `l` | 归属日期次日 04:00 截止 |
| `p` | 0 |
| `o` | 默认排序 |
| `s` | 无步骤 |
| `x` | 不重复 |
| `m` | 系统默认“任务已完成”提示 |
| `h` | 不提醒 |
| `u` | 普通任务 |
| `y` | 新任务按规则推导；已有任务保留原归属日期 |

`i`、`n`、`r`缺失时任务无效。

任务更新不删除：

- 已完成和未完成历史；
- 当时实际获得的积分；
- 完成时间；
- 历史步骤和执行快照；
- 普通备注；
- 信息告知历史；
- 结果变更记录。

已完成实例不会因 Dom 普通更新重新开启。若 Dom 希望 Sub 再执行一次，应复制任务并生成新的 `taskId`。只有 Sub 可以撤销完成；Dom 延期只能重新开启因截止而未完成的任务。

## 9. 日期、任务日与截止时间

### 9.1 格式

```text
日期：YYYY-MM-DD
日期时间：YYYY-MM-DDTHH:mm
时间：HH:mm
```

- 月、日、时、分必须补零；
- 不允许秒、毫秒、时区后缀或空格；
- 不允许 `24:00`；
- 必须是真实存在的日期和时间；
- 全部按照手机当前本地时间解释。

### 9.2 凌晨 4 点任务日

```text
2026-07-20 任务日
开始：2026-07-20 04:00
结束：2026-07-21 04:00
```

### 9.3 截止字段

```json
{"l":"2026-07-20"}
```

表示 2026-07-21 04:00 截止。

```json
{"l":"2026-07-20T22:30"}
```

表示手机本地时间 2026-07-20 22:30 截止。

缺少 `l`时，默认在归属日期次日 04:00 截止。

```json
{"l":null}
```

表示永不截止。永不截止的必做任务会持续计入待完成，并使当日结果保持进行中，直到完成或撤销。

### 9.4 归属日期 `y`

自动推导规则：

- 日期截止：归属于填写的日期；
- 精确时间不早于 04:00：归属于当天；
- 精确时间早于 04:00：归属于前一天；
- 无明确日期：归入导入时的当前任务日；
- 重复实例：归属于计划执行日。

修改 `l`只改变截止时间。已有任务缺少 `y`时保留原归属日期；只有显式提供且不同的 `y`才改变任务归属日期。解析器推导出的日期变化不得触发日期迁移。

单次任务延期时，Dom 可以省略 `y`或显式填写原 `y`。主动显式修改 `y`时，任务及其积分归属转移到新日期，原日期和新日期的结果均重新计算。

### 9.5 时间和时区变化

- 日期时间始终作为本地墙上时间解释；
- 更换时区后，日期和钟点值不变，不保持原 UTC 时刻；
- 状态可以随时间向前推进，但不会因系统时间拨回自动倒退；
- 一旦任务进入未完成，拨回时间不会恢复，只能由 Dom 延期；
- 前台计时使用 Android 单调时钟，不受系统时间修改影响；
- 时间或时区变化会触发通知重新核对和操作日志记录。

## 10. 任务状态与状态转换

任务实例状态：

```text
未开始
待完成
已完成
未完成
已撤销
```

主要转换：

```text
未开始 → 待完成：到达任务日 04:00
未开始 → 已撤销：Dom 撤销
待完成 → 已完成：满足条件并点击完成
待完成 → 未完成：到达截止时间
待完成 → 已撤销：Dom 撤销
已完成 → 待完成：截止前撤销完成
已完成 → 未完成：截止后撤销完成
未完成 → 待完成：Dom 延期至未来
未完成 → 已撤销：Dom 撤销
已撤销 → 未开始/待完成/未完成：重新导入后按当前时间判断
```

规则：

- 只有待完成状态可以操作步骤、计数、计时和告知正文；
- 未开始允许提前填写普通备注；
- 已完成锁定执行数据；
- 未完成必须经过 Dom 延期才能继续；
- 普通备注在任何状态都可以编辑；
- 没有截止时间的任务不会自动进入未完成。

## 11. 步骤任务

```json
{
  "s": [
    {"n":"步骤名称","r":1}
  ]
}
```

- `r=1`：必需步骤；
- `r=0`：选做步骤；
- 步骤没有传输 ID；
- 所有任务都必须由 Sub 主动点击“完成任务”；
- 必需步骤未全部完成时，拒绝完成并突出显示；
- 选做步骤不影响完成；
- 完成后锁定步骤；
- 修改步骤前必须先撤销完成。

任务更新时：

- 新旧步骤名称、顺序和类型完全相同：保留进度；
- 任一结构变化：重置尚未结束实例的步骤进度；
- 已完成、未完成和已撤销实例保留历史快照；
- 导入预览必须提示进度重置。

## 12. 软件内执行方式

执行方式与必做/选做属性相互独立。

```text
缺少 u：普通任务
u.k=1：计数任务
u.k=2：计时任务
u.k=3：信息告知任务
```

统一完成条件：

```text
必需步骤全部完成
+
执行方式目标达成
+
Sub 点击完成任务
```

达标不会自动完成。

### 12.1 计数任务

```json
{
  "u": {
    "k": 1,
    "a": 1,
    "v": 30
  }
}
```

| 字段 | 含义 |
|---|---|
| `k=1` | 计数任务 |
| `a=1` | 拖动计数条 |
| `a=2` | 点击计数 |
| `v` | 目标次数 |

规则：

- 目标为 1～999 的整数；
- 当前计数范围为 0～目标值；
- 拖动条以 1 为步长；
- 点击计数提供减 1 纠错按钮；
- 不允许超过目标；
- 只负责记录，不验证动作真实性；
- 达到目标后解锁完成按钮。

### 12.2 计时任务

```json
{
  "u": {
    "k": 2,
    "v": 600
  }
}
```

- `v`单位为秒，范围 1～3600；
- 最长累计 1 小时；
- 只在任务执行页面位于前台时计时；
- Sub 主动开始，可暂停和继续；
- 多段时间累计；
- 切换页面、切换应用或锁屏时自动暂停；
- 运行时保持屏幕常亮；
- 达标后停止计时并解锁完成按钮；
- 内部按毫秒记录，界面按秒显示；
- 手机重启后保留累计时长，但不自动继续。

### 12.3 信息告知任务

```json
{
  "i": "taskId",
  "n": "告知今日情况",
  "r": 1,
  "d": "请填写需要告知的内容",
  "u": {"k":3}
}
```

信息告知任务用于 Sub 向 Dom 输送信息，而不是让 Sub 阅读确认。

页面包含：

- 任务标题；
- Dom 填写要求；
- 归属日期与截止时间；
- 必填多行纯文本框；
- 普通备注入口；
- 保存草稿；
- 复制告知文本；
- 生成告知图片；
- 系统分享；
- 完成任务。

规则：

- 告知正文最多 2000 个 Unicode 字符；
- 去除首尾空白后不能为空；
- 换行计为一个字符；
- 告知内容与普通备注分开保存；
- 普通备注永远不对 Dom 展示；
- 告知正文填写后仍需点击完成；
- 完成后锁定，撤销完成后可继续修改；
- 日常结果页只显示任务名称和状态，不显示告知正文；
- 已完成的告知内容可以在历史中再次复制、生成图片或分享；
- 告知图片完整生成，不限制高度、不分页、不截断；
- 调用系统分享不等于任务完成，应用无法确认内容是否真正发送。

### 12.4 执行方式更新

- 计数方式或目标变化：重置未结束实例计数；
- 计时目标变化：重置未结束实例计时；
- 普通任务与软件执行任务互相切换：旧执行记录归档，新方式从零开始；
- 信息任务要求更新：保留 Sub 草稿，并提示重新检查；
- 已结束实例不改变；
- 撤销完成后保留计数、计时或告知内容。

### 12.5 `u`组合校验

| 类型 | 必需字段 | 禁止字段 |
|---|---|---|
| `k=1` | `a`、`v` | — |
| `k=2` | `v` | `a` |
| `k=3` | 无 | `a`、`v` |

非法组合整批拒绝导入。

## 13. 重复任务

```json
{
  "x": {
    "f": 2,
    "s": "2026-07-18",
    "e": "2026-08-18",
    "w": [1,3,5],
    "t": "22:00"
  }
}
```

| 字段 | 含义 |
|---|---|
| `f` | 1 每日；2 每周 |
| `s` | 开始日期，缺失则从首次导入任务日开始 |
| `e` | 结束日期，包含当天 |
| `c` | 最大实际生成实例数 |
| `w` | 每周执行日，1～7 为周一至周日 |
| `t` | 每次截止时间；缺失为次日 04:00；`null`为永不截止 |

规则：

- `e`与`c`互斥；
- 两者都缺失表示长期重复；
- `c`必须为正整数；
- 每周任务的 `c`表示实例总数，不是周数；
- `w`不能重复，按升序输出；
- 每周任务必须具有非空 `w`；
- 每日任务不能携带 `w`。

### 13.1 实例生成

Android 在应用打开、任务导入或任务日变化时：

- 检查应生成的实例；
- 只生成截至当前任务日的实例；
- 补建任务已经发布后遗漏的实例；
- 已超过截止时间的补建实例直接标记为未完成；
- 补建实例计入 `c`。

首次导入不补建导入前的实例。首次导入前跳过的日期不占用 `c`。

更新重复模板时：

- 已生成次数不重置；
- `c`小于或等于已生成数量时停止生成；
- 增大 `c`后可以继续；
- 已生成的当前和历史实例保持快照；
- 未来实例使用新版模板；
- 如需重新从第 1 次开始，必须创建新的 `taskId`。

### 13.2 撤销与重新启用

- 撤销模板后不再生成未来实例；
- 未开始、待完成或未完成实例变为已撤销；
- 已完成实例保持已完成；
- 重新启用时不补建撤销期间实例；
- 撤销期间不消耗 `c`；
- 历史已生成实例仍计入 `c`；
- `e`已经过去时不会再生成实例。

## 14. 延期

### 14.1 单次任务延期

Dom 使用相同 `taskId`生成完整新版：

- 省略 `y`以保留原日期，或显式填写原 `y`；
- 设置更晚的 `l`；
- 因截止而未完成的任务重新变为待完成；
- 已完成任务不会重开；
- 新截止时间仍在过去时继续未完成；
- 保留步骤进度和普通备注；
- 记录原截止、新截止和结果变化。

### 14.2 重复任务某次延期

Dom 延期模块：

```text
选择重复模板
→ 选择需要延期的执行日期
→ 设置新截止时间
→ 复制任务内容
→ 删除重复规则
→ 生成新 taskId
→ 生成临时任务
```

- 原重复实例继续保持未完成；
- 新临时任务独立执行和计分；
- 默认复制标题、描述、类型、积分、步骤、提示和积分组；
- 不增加来源关联字段；
- 原模板以后更新不影响延期临时任务。

## 15. 完成、撤销完成与积分

### 15.1 完成

完成时：

- 检查必需步骤和软件执行目标；
- 保存执行快照；
- 锁定执行数据；
- 发放任务积分；
- 显示任务级 `m`完成提示；
- 重新计算积分组及全局当日结果。

### 15.2 撤销完成

截止前：

```text
已完成 → 待完成
```

截止后：

```text
已完成 → 未完成
```

撤销时：

- 扣回本次积分；
- 保留完成时的步骤、计数、计时或告知内容；
- 截止前可继续修改和再次完成；
- 截止后必须由 Dom 延期；
- 保存完整撤销记录。

积分使用流水而不是删除记录：

```text
完成：+10
撤销：-10
再次完成：+10
```

### 15.3 积分规则

- `p`为 0～9999 的非负整数；
- 缺失为 0；
- 不支持小数和负分；
- 步骤不单独计分；
- 必做和选做都可以获得积分；
- 重复任务每个实例独立计分；
- 未开始、待完成、未完成和已撤销不获得积分；
- 修改已完成任务的 `p`不追溯修改过去实际积分。

---

## 16. Dom 撤销任务

顶层字段：

```json
{"z":["taskId1","taskId2"]}
```

规则：

- 不物理删除任务、备注和历史；
- 未开始、待完成和未完成实例变为已撤销；
- 已撤销实例不再影响整体结果；
- 重复模板停止生成未来实例；
- 已完成实例保持已完成，继续显示、计分并参与原日期结果；
- 重新导入相同 `taskId`的完整任务可以解除模板或任务撤销；
- 同一 `taskId`不能同时出现在任务列表和 `z`中。

## 17. 普通备注

- 所有任务始终允许备注；
- 备注仅保存在 Android 本地；
- 任意任务状态下均可编辑；
- 更新任务、延期、移动积分组和备份恢复时保留；
- 不进入 DST1；
- 不显示在结果图片或信息告知图片中；
- Dom 无法通过现有协议读取。

## 18. 本地通知

任务字段：

```json
{"h":[60,10]}
```

- 单位为分钟；
- `0`表示截止时提醒；
- 单任务最多 5 个提醒；
- 范围为 0～10080 分钟；
- 去重后按降序输出；
- 没有截止时间的任务不能设置提醒。

### 18.1 仅发布后通知

每个实例记录 `publishedAt`：

- 单次任务：确认导入时间；
- 重复任务：该次实例实际生成时间；
- 延期临时任务：确认导入时间；
- 撤销后重新启用：重新启用时间。

理论提醒时间：

```text
截止时间 - h 分钟
```

仅当提醒时间不早于 `publishedAt`且晚于当前时间时安排，否则跳过且不补发。

重复模板不会为尚未发布的未来实例预排提醒。补建的过期实例不发通知。

### 18.2 隐私通知

必做任务：

```text
必做任务
有一项必做任务即将截止
```

选做任务：

```text
选做任务
有一项选做任务即将截止
```

通知不显示名称、描述、步骤、积分组、积分、Dom 名称、告知正文或备注。多项同类提醒可以合并，但不显示具体数量。

点击通知后解锁手机并进入对应任务详情。通知不提供快捷完成按钮。

通知允许系统省电策略造成延迟，不申请精确闹钟特殊权限。任务状态不依赖通知是否送达。

## 19. 每日结果计算

### 19.1 积分组结果

计算单位：

```text
groupId + 归属日期
```

- 必做任务全部完成：已完成，显示 `cm`；
- 任一必做任务未完成：未完成，显示 `im`；
- 没有未完成但存在待完成必做任务：进行中；
- 只有选做任务：选做任务记录；
- 全部有效任务撤销：不生成该组结果。

### 19.2 全局结果

结果页顶部跨全部积分组和未分组任务计算：

1. 任一必做任务未完成：未完成；
2. 没有未完成，但存在待完成必做任务：进行中；
3. 所有必做任务完成：全部完成；
4. 没有必做任务，只有选做任务：选做任务记录；
5. 没有任何有效任务：不生成结果页。

全局状态使用 Android 内置文案，不增加传输字段。

### 19.3 过去结果重算

以下操作会重新计算受影响的过去日期：

- 添加归属于过去日期的任务；
- 更新过去任务；
- 延期和重新开启；
- 修改必做或选做属性；
- 移动积分组或归属日期；
- 撤销或恢复任务。

保留结果版本记录，包括变更时间、原结果、新结果、`batchId`、相关 `taskId`和原因。旧版本不会被覆盖。

## 20. 今日结果页面与图片

只生成当前凌晨 4 点制任务日的结果页面，不生成历史日期分享结果。

页面内容：

- 当前任务日；
- Dom 名称；
- 全局状态；
- 本日总积分；
- 各积分组小标题；
- 每个积分组的任务及状态；
- 每组 `cm`或 `im`；
- 未分组任务区。

不显示：

- 普通备注；
- 信息告知正文；
- 任务详细描述；
- 内部 ID；
- 结果变更日志；
- 积分内部流水；
- 状态真正为已撤销的实例。

结果页规则：

- 可以反复生成；
- 生成不会锁定或修改任务；
- 每次使用最新状态；
- 不折叠任务；
- 不显示每日、每周、临时分类；
- 同一积分组内的不同来源任务合并显示；
- 图片高度随任务数量动态增加；
- 不自动分页，生成一张长图；
- 提供生成图片、复制结果和系统分享。

本日总积分为当前任务日所有已完成任务的实际净积分。跨日期累计积分在“我的”页面显示。

## 21. Android 导航与今日页

底部导航固定为：

```text
历史｜今日｜我的
```

默认进入中间的“今日”。

### 21.1 今日页添加任务

- 今日页直接显示当前任务日任务；
- 右下角固定圆形导入悬浮按钮；
- 点击后粘贴 DST1 字符串并进入导入预览；
- 不增加独立添加任务页面；
- Sub 不能手工创建任务。

### 21.2 下拉生成结果

今日列表位于顶部时继续下拉：

```text
显示“继续下拉查看今日结果”
→ 超过触发距离后松手
→ 展开今日结果页面
```

- 未达到距离时回弹；
- 达到距离后完整展开；
- 向上滑动或返回关闭；
- 今日页不使用传统下拉刷新。

### 21.3 今日页自动分类

分类位于积分组上层：

```text
今日
├─ 每日任务
│  └─ 各积分组
├─ 每周任务
│  └─ 各积分组
└─ 临时任务
   └─ 各积分组及未分组
```

分类规则：

```text
x.f=1                         → 每日任务
x.f=2 且 w 包含 4～7 天       → 每日任务
x.f=2 且 w 包含 1～3 天       → 每周任务
缺少 x                         → 临时任务
```

- 不显示“重复任务”分类或重复模板；
- 今日只显示已经生成的当前实例；
- 延期生成的新任务属于临时任务；
- 执行方式不影响分类；
- 空分类自动隐藏。

实例生成时把分类保存为本地快照：`DAILY`、`WEEKLY`或`TEMPORARY`。模板以后更新不改变已生成实例分类，未来实例使用新版规则。

### 21.4 积分组折叠

在每个“分类＋积分组”区块内：

- 1～3 条任务全部显示；
- 超过 3 条默认显示排序后的前 3 条；
- 其余显示“展开其余 N 项”；
- 展开后可以收起；
- 折叠状态仅属于界面；
- 同一积分组出现在不同分类时分别折叠。

### 21.5 Sub 权限

Sub 不能：

- 新建或重命名积分组；
- 修改积分组文案；
- 移动任务积分组；
- 修改标题、描述、积分、必做属性、截止时间、归属日期、步骤结构、重复规则或执行方式。

Sub 可以：

- 导入任务；
- 操作步骤；
- 完成与撤销完成；
- 填写普通备注；
- 执行计数、计时和信息告知；
- 查看历史、积分和统计；
- 本地归档或取消归档积分组；
- 生成结果和分享内容。

## 22. 排序

大多数任务不使用 `o`。

默认排序：

1. 必做任务；
2. 截止时间较早；
3. 无截止时间；
4. 首次导入顺序。

Dom 少量手动调整时：

- 为对应积分组全部现有任务设置 `o`；
- 使用 10、20、30……；
- 将这些任务作为完整新版发送；
- Dom 本地保存 `o`；
- 新增且没有 `o`的任务排在人工排序任务之后；
- 恢复默认排序时，相关任务完整新版全部省略 `o`。

积分组本身不设置 `o`，按首次出现顺序排列。今日列表和结果页使用相同任务排序。

## 24. 我的页面

右上角为设置按钮。

设置使用独立页面，返回后仍停留在“我的”。页面依次提供：

- 外观：跟随系统、浅色、深色，均使用固定应用色板；
- 辅助体验：减少非必要界面动效；
- 通知：显示系统通知状态，首次主动申请权限或打开系统通知设置；
- 隐私与分享：允许下次分享信息告知图片时重新显示隐私提示；
- 关于：显示应用、协议和本地数据库版本，以及本地数据说明。

字体与字号始终跟随系统。主题模式不改变生成的分享图片。设置页不允许修改任务日边界、任务提醒时间或任务内容。

顶部概览：

- 累计总积分；
- 本日积分；
- 已完成任务数；
- 必做任务完成率。

必做任务完成率：

```text
已完成必做任务数
÷
（已完成 + 未完成 + 待完成的必做任务数）
```

- 已完成计入分子和分母；
- 未完成、待完成只计入分母；
- 未开始、已撤销和选做任务不计入；
- 没有已开始必做任务时显示“—”；
- 永不截止的待完成必做任务持续计入分母。

其他统计：

- 最近 7 日和 30 日积分变化；
- 各积分组累计积分；
- 必做与选做完成数量；
- 每日、每周、临时任务完成数量；
- 完成、未完成和撤销数量；
- 积分流水；
- 已归档积分组。

统计图不显示告知正文、普通备注或任务描述。

## 25. Dom 网页界面

主要页面：

```text
创建任务｜任务库｜积分组
```

### 25.1 创建任务

采用二级菜单：

```text
本次任务批次
├─ 积分组 A
│  ├─ 任务 1
│  └─ 任务 2
├─ 积分组 B
│  └─ 任务 3
└─ 未分组
```

- 手机端积分组可展开和折叠；
- 每个积分组下可以添加任务；
- 任务可以拖动到其他积分组；
- 一个字符串可以包含多个积分组；
- 最终只生成一个 `batchId`和 CRC32；
- 页面显示任务数、JSON 大小和最终字符串长度。

任务编辑字段包括：积分组、名称、描述、必做属性、日期、截止时间、积分、步骤、执行方式、重复规则、提醒和完成提示。

### 25.2 任务库

- 搜索和按积分组筛选；
- 编辑并生成完整新版；
- 复制为新任务并生成新 `taskId`；
- 单次延期；
- 重复任务某次延期为临时任务；
- 撤销与恢复；
- 少量拖动排序；
- 粘贴旧字符串恢复任务。

任务库不显示 Sub 状态。

### 25.3 积分组

- 新建积分组；
- 修改名称、完成文案和未完成文案；
- 查看本地 `groupId`；
- 生成积分组局部更新；
- 删除网页本地配置；
- 导出和导入配置。

### 25.4 响应式布局

- 手机端使用底部导航；
- 桌面端使用左侧导航；
- 草稿自动保存；
- IndexedDB 需要版本迁移；
- 清除浏览器数据前提示导出配置。

## 26. 导入验证与预览

采用整批原子导入：

```text
全部有效 → 预览 → 确认 → 一次性写入
任一无效 → 整批拒绝
```

整批拒绝包括：

- 协议前缀、Base64URL、CRC32或解压失败；
- JSON结构错误；
- 必需字段缺失；
- 日期、ID、文本、数组或整数越界；
- 未知关键枚举；
- `e`和`c`同时存在；
- 重复 `groupId`；
- 同一 `taskId`在字符串中多次出现；
- 同一 `taskId`同时出现在任务列表和 `z`；
- `u`字段组合非法；
- 协议版本不受支持。

导入预览按积分组显示：

- 新增任务；
- 更新任务；
- 未变化任务；
- 撤销任务；
- 积分组或日期移动；
- 延期和重新开启；
- 步骤或软件执行进度重置；
- 历史积分转移；
- 历史结果变化。

用户取消时不写入任何数据。确认后在一个 Room 事务内完成更新、移动、撤销、积分和结果重算。

## 27. 字段与安全上限

| 内容 | 上限 |
|---|---:|
| Dom 名称 `d` | 50 字符 |
| 批次说明 `m` | 500 字符 |
| 积分组名称 `n` | 50 字符 |
| `cm`、`im` | 各 500 字符 |
| 任务名称 `n` | 100 字符 |
| 任务描述 `d` | 2000 字符 |
| 单任务完成提示 `m` | 500 字符 |
| 步骤名称 | 100 字符 |
| 单任务步骤 | 50 个 |
| 单任务提醒 | 5 个 |
| 提前提醒 | 0～10080 分钟 |
| 一个字符串的积分组条目 | 50 个 |
| 全部分组与未分组任务 | 100 条 |
| 撤销任务 ID | 100 个 |
| 信息告知正文 | 2000 字符 |
| 计数目标 | 1～999 |
| 计时目标 | 1～3600 秒 |
| 单任务积分 | 0～9999 |

整体限制：

- 输入字符串最大 128 KiB；
- Base64URL 解码后压缩数据最大 96 KiB；
- 解压后 JSON 最大 256 KiB；
- 超过限制直接拒绝；
- 文本按 Unicode 码点计数；
- 普通文本必须已经是 Unicode NFC；非 NFC 输入整批拒绝，不自动转换；
- ID 不进行 Unicode 或大小写转换；
- 文本保留换行、去除首尾无意义空白；
- 空字符串只允许用于协议明确规定的清除操作。

数组规则：

- `w`唯一并升序；
- `h`唯一并降序；
- 步骤保持输入顺序；
- 任务数组顺序本身不决定最终显示顺序。

## 28. Android 本地数据模型

建议 Room 表：

| 表 | 作用 |
|---|---|
| `app_profile` | Dom 名称及全局设置 |
| `import_batch` | 批次、说明和导入结果 |
| `task_group` | 积分组与归档状态 |
| `task_definition` | 当前任务定义与重复模板 |
| `task_step_definition` | 模板步骤 |
| `task_instance` | 实际任务实例与快照 |
| `instance_step` | 实例步骤进度 |
| `execution_progress` | 计数和计时进度 |
| `information_submission` | 告知草稿和正文 |
| `task_note` | 普通备注 |
| `points_ledger` | 积分流水 |
| `result_revision` | 每日结果版本 |
| `action_log` | 完成、延期、移动等事件 |
| `reminder_record` | 已发布实例的通知安排 |

所有任务均分为定义和实例两层。单次任务也生成一个实例；重复任务生成多个实例。

积分流水主要记录 `taskId`、实例键、积分变化、时间和原因。统计时根据任务当前积分组归类，因此移动积分组后历史积分自动转移。

统计缓存不得作为恢复后的最终依据，应由业务记录重新计算。

## 29. 本地备份与恢复

### 29.1 备份格式

```text
备份 JSON
→ UTF-8
→ zlib 压缩
→ CRC32
→ DSTB1 文件
```

- 扩展名 `.dstb`；
- 不设置密码；
- 不加密；
- Android 系统云备份禁用；
- 获得文件的人可以读取任务、告知正文和备注，导出页显示一次提示。

备份包含设置、积分组、任务、实例、步骤、计数、计时、告知正文、备注、积分流水、导入记录、操作日志和结果版本。系统通知安排不备份，恢复后重新生成。

### 29.2 完全替换

- 恢复前生成应用内部临时回滚快照；
- 清空当前业务数据；
- 导入备份；
- 重新计算状态、积分、结果和通知；
- 失败时自动回滚；
- 成功后删除临时快照。

### 29.3 合并恢复

| 数据 | 合并规则 |
|---|---|
| 积分组、任务定义 | 相同 ID 保留 `updatedAt`较新版本 |
| 任务实例 | 按 `taskId + occurrenceKey`合并 |
| 步骤、计数、计时 | 保留更新时间较新的进度 |
| 告知正文、普通备注 | 保留更新时间较新的内容 |
| 导入批次 | 按 `batchId`去重 |
| 积分流水 | 按流水 ID 去重后合并 |
| 操作日志 | 按事件 ID 去重后合并 |
| 结果版本 | 按版本 ID 去重后合并 |
| 通知 | 不合并，重新生成 |

更新时间相同但内容不同时，默认保留本机版本，并允许用户选择备份版本。

## 30. Android 权限与隐私

不申请：

- `INTERNET`；
- 摄像头、麦克风；
- 定位；
- 联系人；
- 活动识别和身体传感器；
- 广泛文件或照片读取；
- 精确闹钟特殊权限；
- 悬浮窗；
- 无障碍服务。

需要：

- Android 13 及以上的通知权限；
- `RECEIVE_BOOT_COMPLETED`，用于重启后核对提醒；
- 普通通知振动能力。

备份使用系统文件选择器，不申请广泛存储权限。计时保持屏幕常亮不需要额外权限。

通知权限被拒绝时其他功能正常；应用不反复请求，只在用户主动进入设置时引导。

所有页面允许系统截图和录屏，不提供应用锁，最近任务预览使用 Android 普通行为。
