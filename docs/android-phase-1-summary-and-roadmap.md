# Android 第一阶段总结与多窗口后续路线图

> 总结基线：`440bf61 实现 Android 第一阶段任务导入与执行`  
> 整理日期：2026-07-18  
> 需求基准：`docs/preview.md`  
> 当前分支：`main`

## 1. 第一阶段目标与结论

第一阶段没有尝试完成全部 Android 产品功能，而是建立可持续扩展的协议、领域、数据库和测试基础。当前已经形成以下最小闭环：

```text
粘贴 DST1
→ CRC32、zlib、UTF-8 与 JSON 校验
→ 导入变更预览
→ 用户确认
→ Room 单事务写入
→ 今日页读取任务实例
→ 领域服务执行步骤、完成与撤销完成
→ 写入操作日志和积分流水
```

构建和测试基线：

- `testDebugUnitTest`：4 个测试套件，15 个测试，0 失败；
- `assembleDebug`：通过；
- Debug APK：`app/build/outputs/apk/debug/app-debug.apk`；
- 测试报告：`app/build/reports/tests/testDebugUnitTest/index.html`；
- 当前没有真机或模拟器仪器测试；
- 构建存在 Android SDK XML 新旧工具版本警告，但不影响测试和 APK。

## 2. 已实现能力

### 2.1 DST1 协议入口

- 校验 `DST1.<payload>.<checksum>` 三段格式；
- 强制无填充 Base64URL；
- CRC32 校验；
- zlib 解压；
- 严格 UTF-8 解码；
- 输入、压缩数据和解压 JSON 大小限制；
- 严格 JSON 字段白名单；
- ID、日期、日期时间、文本长度、整数范围和集合重复校验；
- 同批次重复 `groupId`、`taskId` 及任务与 `z` 冲突校验；
- 普通、步骤、计数、计时、信息告知和重复任务解析；
- 对 `h` 返回明确的“当前构建尚未实现”错误。

关键文件：

- `protocol/Dst1Decoder.kt`
- `protocol/Dst1Parser.kt`
- `protocol/DstModels.kt`
- `protocol-test-vectors/`

### 2.2 导入与预览

- 预览新增、更新、未变化、撤销、恢复、移动和步骤重置；
- 相同 `batchId` 防重复导入；
- 积分组局部更新；
- 任务定义完整替换；
- 定义和实例分离；
- 已完成实例不被普通更新重新开启；
- 已完成实例收到 Dom 撤销时继续保持已完成和计分；
- 确认后使用 Room 单事务写入；
- 事务中后续写入失败时，前面的定义、实例和批次记录全部回滚。

关键文件：

- `data/ImportService.kt`
- `data/AppDao.kt`

- 完成时追加正向积分流水；
- 撤销完成时追加负向冲正流水，不删除原记录；
- 每次关键操作追加不可变 `action_log`；

## 3. 当前 Room 数据模型

| 表 | 当前作用 |
|---|---|
| `app_profile` | Dom 名称和全局资料入口 |
| `import_batch` | 已导入批次与批次说明 |
| `task_group` | 积分组定义和文案 |
| `task_definition` | Dom 下发的最新任务定义 |
| `task_step_definition` | 最新定义中的步骤 |
| `task_instance` | 实际执行实例和导入快照 |
| `instance_step` | 实例步骤进度 |
| `points_ledger` | 正向积分与冲正流水 |
| `action_log` | 导入、更新、完成等操作事件 |

数据库当前为版本 2，并允许破坏性重建。这只适用于测试阶段；真实使用前必须冻结模型并提供正式 Room migration。

## 4. 已确认的临时规则与技术债

### 4.1 积分组移动临时规则

当前任务移动积分组后：

- 已有积分流水保留完成当时的原 `groupId`；
- 后续完成产生的积分进入新 `groupId`；
- 同一任务可能在多个积分组留下历史积分。

这与需求稿中“移动后历史积分一并转移并重算结果”的正式语义不同。实现历史结果重算时必须移除此规则，并生成结果修订记录。

### 4.2 测试构建能力限制

协议仍保持 DST1 v1，但当前构建整批拒绝：

- `h`：提醒；

W10 已支持 `u.k=1/2/3` 的计数、计时和信息告知能力；W11 已支持 `x.f=1/2` 的每日和每周重复能力。

从“不支持”变为“支持”不需要升级协议。只有字段或业务语义发生不兼容变化才升级主版本。

### 4.3 其他已知缺口

- 状态校正按具体任务触发，尚无全局前台/后台调度器；
- 没有仪器测试、截图测试和无障碍测试；
- 通知 Receiver 仍为空骨架；
- 未实现备份、恢复、结果图片和分享。

## 5. 多窗口协作原则

1. 每个窗口使用独立 Git 分支或 worktree，不要让多个窗口直接修改同一个工作区。
2. 每个窗口开始前先阅读：
   - `docs/preview.md`
   - 本文档
   - `docs/android-phase-1.md`
3. 每个窗口只完成一个明确交付，不顺手扩展相邻功能。
4. 涉及 DST1 字段时必须同步更新：协议模型、解析器、独立测试向量和测试。
5. 涉及 Room 表结构时必须同步更新：Entity、DAO、数据库版本、migration 和数据库测试。
6. 每个窗口交付前至少运行：

```powershell
./gradlew.bat testDebugUnitTest assembleDebug
```

7. 窗口交接必须说明：修改文件、数据结构变化、协议变化、测试结果和仍未解决的问题。

  W23 历史 UI
  W24 今日结果与分享图片
