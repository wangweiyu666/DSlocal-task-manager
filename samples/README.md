# 可导入样例

本目录提供合成手动体验数据，不是自动化协议清单；不会自动导入、部署或写入真实账号。当前任务字段覆盖 k=1～7 与直接完成，旧客户端可能拒绝新增类型。

| 样例 | 用途 |
| --- | --- |
| [current-features.json](current-features.json) / [任务码](current-features.dst1) | 8 个任务：直接、计数、计时、自动保存信息、心情、通知、单选和连续条件步骤；省略日期、无截止，可按首次导入任务日体验 |
| [current-exception.json](current-exception.json) / [任务码](current-exception.dst1) | 每日重复＋DST1.1 单日选项覆盖；提交文件日期固定为 2026-09-12，仅用于阅读和解析；实际体验用下面生成命令 |

## 生成本次体验数据

Node 22+，先在 web 目录 `npm ci`。仓库根目录运行：

```text
node samples/generate.mjs --fresh
node samples/generate.mjs --fresh --date 2026-09-12
```

默认按本机 04:00 换日取得任务日；跨时区验收应显式指定日期。每次生成全新批次、组、任务、步骤和选项 ID，并同步改写分支引用；输出在忽略的 `build/samples/current-features.*`、`current-exception.*`，下次生成覆盖这些临时文件。不会修改提交的旧样例；相同已生成批次重复导入仍会被拒绝。

预期体验：信息输入立即完成时先保存；通知须主动确认；独立单选基础 2 分，选五分项完成得 7 分、零分项得 2 分。连续步骤基础 10 分：路线 A 确认通知、选择“继续填写”并确认信息后得 17 分；A 跳过选做选择或选“不填写”得 13 分；路线 B 确认通知后得 10 分。未匹配分支隐藏；切换已确认选择须先撤销，草稿恢复后仍需重新确认。以上是样例预期，不是本轮设备测试通过记录。

单日例外示例基础 2 分，当天 A 选项为 7 分，完成得 9 分；模板其他计划日 A 为 1 分，完成得 3 分。各日答案独立。新生成文件中的日期是指定日期，提交文件中的固定日期不会自动跟随今天。

## 维护与兼容

```text
node samples/generate.mjs --check
node samples/generate.mjs --write
```

check 调用实际 Web/共享协议编解码器，检查两组 JSON 与任务码语义一致，并解析三份旧任务码；不运行完整产品回归。write 仅在编辑这两个 JSON 后更新其对应任务码，使用固定源 ID，适合提交。新生成批次使用 fresh，不能只改压缩任务码中的文本。

旧 `test-import-2026-07-20.dst1`、`w24-manual-2026-07-22.dst1` 和 `today-real-use-2026-08-03.dst1` 保持原字节供兼容读取；其中日期和截止可能过期，不再作为今天的验收步骤。Android 的样例解析测试继续读取根目录任务码。更多规范见 [DST1 契约](../docs/dst1-test-vectors.md)。
